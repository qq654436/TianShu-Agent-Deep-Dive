## 正文

兄弟们，今天拆解了一个让我眼前一亮的开源项目 —— **GSD (Get Shit Done)**。

名字就很直白对吧？"把事情做完"，不整那些虚的。

### 🎯 它解决什么问题？

你有没有这种感觉：

用 AI 写代码，刚开始挺好的，对话越久质量越差...

AI 开始说"我会更简洁"，然后代码越来越烂。

这叫 **"上下文腐烂" (Context Rot)** —— 上下文窗口被填满后，AI 记不住前面的重要信息了。

GSD 就是来解决这个问题的。

### 💡 核心思路

**把项目状态外部化，不依赖 AI 的记忆。**

传统方式：
```
[对话历史 1] + [对话历史 2] + ... + [当前任务]
→ 上下文满了 → 质量下降 ❌
```

GSD 方式：
```
[CONTEXT.md] + [STATE.md] + [当前任务]
→ 只加载相关信息 → 质量稳定 ✅
```

简单说，就是把所有决策、需求、状态都写到 Markdown 文件里。

AI 每次只读必要的上下文，永远保持"新鲜"的 200k tokens 可用。

### 🔥 工作流程

1️⃣ **/gsd:new-project** - 描述想法，AI 追问直到完全理解
2️⃣ **/gsd:discuss-phase 1** - 捕获你的偏好 (布局/API/内容风格)
3️⃣ **/gsd:plan-phase 1** - 生成原子任务计划 (XML 格式化)
4️⃣ **/gsd:execute-phase 1** - 波次执行，并行推进，自动 git commit

最爽的是第 4 步 —— **波次执行**。

系统会分析任务依赖关系：
- 无依赖的任务 → 并行执行
- 有依赖的任务 → 顺序执行

你出去喝杯咖啡回来，代码已经写好了，git 历史干干净净。

### 🤖 技术亮点

- **元提示系统** - 提示的提示，结构化生成指令
- **子代理编排** - 研究/规划/执行/验证，四个代理各司其职
- **XML 提示格式化** - 提高 AI 输出质量和一致性
- **原子提交** - 每个任务独立 commit，历史清晰

### 🎓 我的收获

GSD 和天枢计划有很多相似理念：

✅ 外部化状态管理 (GSD 用 CONTEXT.md，天枢用 memory/)
✅ 多层验证机制
✅ 子代理编排
✅ 文档驱动开发

但 GSD 更轻量，专注于"写代码"这一件事。

天枢更像一个"一人公司操作系统"，涵盖业务运营、情报监控、周期性任务等。

**可以借鉴的点**:
1. XML 提示格式化 → 提高子代理输出质量
2. 波次执行 → 优化并行任务调度
3. CONTEXT.md 模式 → 增强用户偏好捕获
