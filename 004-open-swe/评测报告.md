## 🎯 产品定位

**一句话描述**: 开源版企业内部编码 Agent，基于 LangGraph + Deep Agents，支持 Slack/Linear/GitHub 触发、云沙箱隔离、自动 PR 创建

**目标用户**: 
- 工程团队 (10+ 开发者)
- AI 工作流建设者
- 企业内部工具开发者

**解决痛点**:
1. 编码 Agent 与内部系统脱节 → Slack/Linear 原生集成
2. 代码执行安全风险 → 云沙箱隔离
3. 多任务并行效率低 → 子代理编排 + 独立沙箱
4. PR 流程繁琐 → 自动提交 + 开 PR

## 🏗️ 技术架构

### 核心组件

```
┌─────────────────────────────────────────────────────────┐
│                 触发层 (Invocation)                      │
│  Slack Bot │ Linear Bot │ GitHub App                    │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│              编排层 (Orchestration)                      │
│  LangGraph + Deep Agents                                │
│  - 主 Agent (协调)                                       │
│  - 子代理 (并行任务)                                     │
│  - Middleware (确定性钩子)                               │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│               工具层 (Tooling)                           │
│  execute │ fetch_url │ http_request                     │
│  commit_and_open_pr │ linear_comment │ slack_reply      │
│  read_file │ write_file │ edit_file │ ls │ grep         │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│              沙箱层 (Sandbox)                            │
│  Modal │ Daytona │ Runloop │ LangSmith                  │
│  (独立 Linux 环境，完整 Shell 权限)                        │
└─────────────────────────────────────────────────────────┘
```

### 数据流

1. **触发**: Slack 提及 / Linear 评论 / GitHub PR 评论
2. **上下文组装**: 读取 AGENTS.md + Issue/Thread 完整历史
3. **沙箱创建**: 在选定提供商创建独立沙箱，克隆仓库
4. **Agent 执行**: 主 Agent 协调，可 spawn 子代理
5. **Middleware 钩子**: 注入 follow-up 消息、自动 PR 创建
6. **结果回传**: PR 链接 / Slack 回复 / Linear 评论

### 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 编排框架 | LangGraph + Deep Agents | 可组合，有升级路径 |
| 沙箱隔离 | 云沙箱 (Modal/Daytona 等) | 安全，可并行，易扩展 |
| 工具集 | ~15 个精选工具 | 质量 > 数量，降低幻觉 |
| 触发方式 | Slack/Linear/GitHub | 工程师工作流原生集成 |
| 上下文注入 | AGENTS.md + Issue 历史 | 编码规范 + 任务背景 |

## 💡 创新点

### 1. 企业级架构模式

Open SWE 不是从零构建，而是复用了 Stripe Minions、Ramp Inspect、Coinbase Cloudbot 的核心模式：

| 公司 | 项目 | 核心模式 |
|------|------|----------|
| Stripe | Minions | 蓝图文档 + 确定性节点 |
| Ramp | Inspect | OpenCode 组合 + 子会话 |
| Coinbase | Cloudbot | Slack 原生 + Agent 委员会 |
| **Open SWE** | **Open SWE** | **LangGraph + 沙箱 + Middleware** |

### 2. 沙箱隔离优先

**原则**: `Isolate first, then give full permissions inside the boundary`

- 每个任务独立沙箱
- 沙箱可自动重建
- 多任务并行无冲突
- 支持 4+ 提供商 (Modal, Daytona, Runloop, LangSmith)

### 3. Middleware 确定性钩子

弥补 LLM 不可靠性的关键设计：

```python
middleware=[
    check_message_queue_before_model,  # 注入 follow-up 消息
    open_pr_if_needed,                 # 自动 PR 安全网
    ToolErrorMiddleware(),             # 错误处理
]
```

### 4. AGENTS.md 规范

仓库级 Agent 指令文件，类似 Stripe 的 rule files：

```markdown
# AGENTS.md

## 代码规范
- 使用 TypeScript
- 所有函数必须有类型注解
- 测试覆盖率 > 80%

## 架构决策
- 使用 Redux 管理状态
- API 采用 RESTful 风格

## 测试要求
- 运行 `npm test` 验证
- 截图对比 UI 变更
```

## 🔧 技术亮点

### 1. 多触发器路由

```python
# Slack: @openswe repo:owner/name fix login bug
# Linear: @openswe 评论在 issue 上
# GitHub: @openswe 评论在 PR 上

def route_message(platform, thread_id):
    # 确定性 thread ID，follow-up 消息路由到同一 Agent
    return get_or_create_agent(thread_id)
```

### 2. 子代理编排

```python
# 主 Agent 可 spawn 子代理并行任务
subagent = await spawn_subagent(
    task="Write unit tests for auth module",
    middleware=[...],
    todo_list=["test_login", "test_logout", "test_refresh"]
)
```

### 3. Follow-up 消息注入

```python
# 用户可在 Agent 运行时发送 follow-up
# Middleware 在下次 model call 前注入
def check_message_queue_before_model(agent_state):
    new_messages = get_new_messages(agent_state.thread_id)
    if new_messages:
        agent_state.context.extend(new_messages)
```

### 4. 自动 PR 安全网

```python
# 如果 Agent 忘记开 PR，Middleware 兜底
def open_pr_if_needed(agent_state):
    if agent_state.has_changes and not agent_state.pr_created:
        commit_and_open_pr(
            branch=agent_state.branch,
            title=agent_state.pr_title,
            draft=True  # 默认 draft，需人工 review
        )
```

## ⚠️ 局限性

1. **部署复杂度**: 需要配置多个服务 (Slack App, Linear API, GitHub App, 沙箱提供商)
2. **成本**: 云沙箱按运行时间计费，高频使用成本高
3. **延迟**: 沙箱冷启动需要 10-30 秒
4. **学习曲线**: 需要理解 LangGraph + Deep Agents 架构
