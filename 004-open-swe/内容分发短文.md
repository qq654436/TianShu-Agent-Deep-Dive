# Open SWE 深度拆解：企业级 AI Agent 的架构秘密

## 现象背后的趋势

2026 年 3 月 20 日，LangChain 开源了 Open SWE，一个"企业内部编码 Agent"框架。单日 965 星的成绩背后，揭示了一个重要趋势：**AI Agent 正在从玩具走向生产**。

这不是 LangChain 的偶然之作，而是对 Stripe Minions、Ramp Inspect、Coinbase Cloudbot 等顶级工程团队内部架构的开源复刻。

## 四大核心架构决策

### 决策 1：沙箱隔离优先

**原则**: `Isolate first, then give full permissions inside the boundary`

这是 Open SWE 最重要的设计决策。每个任务运行在独立的云沙箱中：
- Modal / Daytona / Runloop / LangSmith 多提供商支持
- 完整 Linux 环境，root 权限
- 任务结束后自动销毁
- 多任务并行无冲突

为什么如此重要？

传统 Agent 直接在主机执行代码，风险极高：
- 误删文件
- 泄露密钥
- 污染环境
- 无法并行

沙箱隔离后：
- 爆破半径限制在沙箱内
- 可给予完整权限（因为隔离了）
- 天然支持并行
- 环境一致性保证

这是 Stripe、Ramp、Coinbase 三家不约而同的选择。

### 决策 2：Middleware 确定性钩子

LLM 不可靠，如何保证关键步骤一定执行？

Open SWE 的答案：Middleware 钩子。

```python
middleware=[
    check_message_queue_before_model,  # 注入 follow-up 消息
    open_pr_if_needed,                 # 自动 PR 安全网
    ToolErrorMiddleware(),             # 错误处理
]
```

**before_model 钩子**：
在每次 LLM 调用前执行，可以：
- 注入用户 follow-up 消息（用户可在 Agent 运行时发消息）
- 限流检查
- 上下文裁剪

**after_agent 钩子**：
在 Agent 完成后执行，可以：
- 检查是否有代码变更
- 自动提交并开 PR（如果 Agent 忘了）
- 运行测试验证
- 发送通知

这是"确定性 + 概率性"混合架构的精髓：
- LLM 负责创造性工作（写代码、调试）
- Middleware 负责确定性工作（提交、开 PR、验证）

### 决策 3：AGENTS.md 规范注入

类似 Stripe 的 rule files，Open SWE 支持仓库级规范文件：

```markdown
# AGENTS.md

## 代码规范
- 使用 TypeScript
- 所有函数必须有类型注解
- 测试覆盖率 > 80%

## 架构决策
- 使用 Redux 管理状态
- API 采用 RESTful 风格

## 测试要求
- 运行 `npm test` 验证
- 截图对比 UI 变更
```

这个文件会被自动读取并注入系统提示，确保 Agent 遵循团队规范。

为什么有效？

1. **可版本控制**：AGENTS.md 随代码库一起管理
2. **可审查**：团队可以讨论和修改规范
3. **可继承**：新成员（和 Agent）自动遵循规范
4. **可演化**：随团队成长迭代

### 决策 4：多触发器统一路由

Open SWE 支持三种触发方式：

**Slack**:
```
@openswe repo:aether-sync/openclaw fix login bug
```

**Linear**:
在 issue 下评论 `@openswe`

**GitHub**:
在 PR 下评论 `@openswe` 请求修改

关键设计：
- 每个 thread 生成确定性 ID
- follow-up 消息路由到同一 Agent
- 支持多任务并行（每个任务独立沙箱）

## 技术架构拆解

### 分层架构

```
┌─────────────────────────────────────────┐
│         触发层 (Slack/Linear/GitHub)     │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│         路由层 (Thread ID + 消息队列)     │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│    编排层 (LangGraph + Deep Agents)      │
│    - 主 Agent (协调)                     │
│    - 子代理 (并行任务)                   │
│    - Middleware 钩子                     │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│         沙箱层 (Modal/Daytona/...)       │
└─────────────────────────────────────────┘
```

### 子代理编排

主 Agent 可以 spawn 子代理并行任务：

```python
# 主 Agent
subagent = await spawn_subagent(
    task="Write unit tests for auth module",
    middleware=[...],
    todo_list=["test_login", "test_logout", "test_refresh"]
)
```

每个子代理有：
- 独立的 Middleware 栈
- 独立的 TODO 列表
- 独立的文件操作空间

这类似 Ramp 的"child sessions"模式。

### 性能优化

| 优化点 | 策略 | 效果 |
|--------|------|------|
| 沙箱冷启动 | 预 warm 池 | 3-5s → 1-2s |
| API 缓存 | 双层缓存 | 减少 90% 调用 |
| 并行执行 | 独立沙箱 | N 倍吞吐 |
| 上下文裁剪 | 智能摘要 | 节省 50% token |

## 与竞品对比

| 特性 | Open SWE | Stripe Minions | Ramp Inspect | Coinbase Cloudbot |
|------|----------|----------------|--------------|-------------------|
| 框架 | LangGraph | 自研 (Goose fork) | OpenCode | 自研 |
| 沙箱 | 可插拔 | AWS EC2 (预 warm) | Modal (预 warm) | 自研 |
| 工具数 | ~15 (精选) | ~500 (每 Agent) | OpenCode SDK | MCPs + Skills |
| 触发器 | Slack/Linear/GitHub | Slack + 按钮 | Slack/Web/Chrome | Slack |
| 验证 | Prompt + PR 安全网 | 3 层 (本地 +CI+ 重试) | 视觉 DOM 验证 | Agent 委员会 |

Open SWE 的优势：
- **开源**: 可审计、可定制、可贡献
- **可组合**: 基于 LangGraph + Deep Agents
- **多提供商**: 不绑定单一沙箱服务
- **文档完善**: INSTALLATION.md + CUSTOMIZATION.md

## 对 OpenClaw 的启发

作为 Aether-Sync 的架构师，我从 Open SWE 看到了三个关键启示：

### 1. 安全是第一位

沙箱隔离不是可选项，是必选项。OpenClaw 必须实现：
- 云沙箱代码执行
- 权限边界控制
- 审计日志

### 2. 确定性钩子弥补 LLM 不可靠

OpenClaw 已有 before_tool/after_tool 钩子，需要增强：
- 自动 PR 安全网
- Follow-up 消息注入
- 测试验证钩子

### 3. 规范注入提升质量

OpenClaw 正在实现 AGENTS.md 支持：
- 读取 workspace AGENTS.md
- 注入系统提示
- 支持热重载

Open SWE 的开源标志着一个转折点：**企业级 AI Agent 架构不再是秘密**。

Stripe、Ramp、Coinbase 花重金构建的内部系统，现在开源可用。这降低了 AI Agent 的入门门槛，也提高了行业标准。

对于 OpenClaw，这意味着：
